# 탐색 안내 모듈 스펙 (`org.rsage.explore`)

_2026-10-23 · [모듈 작성 가이드](../module-authoring-guide.md) 3장의 스펙 형식을 따른다. 계획 문서: [자동 탐색적 데이터 분석(AEDA) 모듈 계획](https://claude.ai/artifact/HL39oANrFzfhdNhFcFtvsN)_

## 1. 목적

데이터를 처음 받았을 때 "무엇이 눈에 띄고, 어디를 더 살펴봐야 하나"에 답한다. 모든 분석을 대신하지 않는다. 찾은 것(신호)마다 근거 수치, 작은 그림, 이어서 할 분석을 카드로 보여 주는 길잡이다.

- 계산은 R이 한다. 같은 데이터와 옵션이면 언제나 같은 신호 표가 나온다.
- 순위는 효과크기로 매긴다. 수백 개 조합을 한꺼번에 보므로 p값은 쓰지 않는다.
- 카드는 탐색 결과다. 결과 끝에 항상 그렇게 알린다(`exploratory`).

단계: 0.1은 R 프로필, 규칙 힌트, 다음 분석 버튼이다. 0.2는 질문 맞춤 힌트(질문 칸, 질문 칩, 변수 뜻 추측, 숫자 대조)와 확인용 데이터 떼어 두기다(6·7장). 0.3은 빠른 모형, 하위집단, 상호작용, 무리, 동떨어진 행, 집단 비교와 표 1 초안이다(8장). 1.0에서 어시스턴트가 데이터를 열면 이 모듈을 먼저 권한다.

## 2. 백엔드

- **datawizard** (필수): 왜도·첨도.
- 상관, η², Cramér V는 base R로 직접 계산한다. 모든 쌍을 돌기 때문에 함수 호출 비용을 줄이려는 것이다. 공식은 effectsize와 같다(η² = SSB/SST, V = √(χ²/(n(k−1))), 편향 보정 없음).
- 그림은 ggplot2.
- dlookr·DataExplorer 같은 큰 EDA 패키지는 쓰지 않는다. 모두 한꺼번에 다 보여 주는 방식이고 의존성이 크다.

## 3. 무엇을 찾는가 → 결과

| 분류 | 신호(kind) | 계산 | 카드의 다음 분석 |
| --- | --- | --- | --- |
| 데이터 상태 | `health` | 중복 행, 빈 열·값이 하나뿐인 열, 숫자 열에 섞인 글자(80% 이상 숫자), 결측 코드로 보이는 값(-99, 999 등이 2번 이상, 나머지와 동떨어짐) | 데이터 점검 |
| 결측 | `missing` | 결측 5% 이상인 변수, 완전한 행 비율 | 결측 데이터 |
| 결측 | `missing_related` | 결측 지시자와 다른 수치 변수의 점이연 r, 범주 변수와는 η. 0.2 이상 | 결측 데이터(그림자 분포 또는 그룹별 결측) |
| 구조 | `scale` | 이름이 `접두사+번호`이고 값 범위가 같은 문항 3개 이상. Cronbach α, 합계 열(합과 r > 0.9) | 신뢰도, 요인분석 (예정) |
| 구조 | `repeated` | ID 이름의 열이 반복되거나, 시점 열이 있을 때 수준 10개 이상인 범주가 반복 | 혼합모형 (예정) |
| 구조 | `wide` | `_pre/_post`, `_t1/_t2`, `_bl/_fu` 같은 접미사의 수치 열 묶음 | 대응 t 검정, 혼합모형 (예정) |
| 분포 | `skew`, `zeros`, `ceiling`, `bimodal` | |왜도| ≥ 1; 0이 30% 이상인 개수; 끝값 비율 ≥ max(15%, 2/고유값 수); 이봉 계수 > 0.6 | — |
| 분포 | `imbalance`, `rare_levels` | 한 범주 90% 이상; 5% 미만 범주 | — |
| 관계 | `association` | 수치끼리 Spearman ρ, 범주끼리 Cramér V. 0.3 이상 | 선형 회귀, 교차표(예정), 이분 변수면 로지스틱 회귀 |
| 관계 | `nonlinear`, `outlier_driven` | |ρ| − |r| ≥ 0.15 / |r| − |ρ| ≥ 0.2 | 선형 회귀 / 데이터 점검 |
| 관계 | `redundant` | |r| ≥ 0.95 또는 V ≥ 0.95 | — |
| 집단 차이 | `group_diff` | 범주별 수치 변수의 η² ≥ 0.06 | t 검정·분산분석(예정), 범주 설명변수 선형 회귀 |
| 목표 변수 | `target_model`, `target` | 목표와 모든 변수의 관련 크기(|ρ|, η, V) 순위 | 결과 유형에 맞춘 회귀(이분 → 로지스틱, 음이 아닌 정수이고 평균 < 10이거나 0이 많거나 치우침 → 개수, 그 밖의 수치 → 선형), 관련 0.1 이상 상위 5개 |

같은 척도의 문항끼리, 문항과 그 합계, 시점별 열끼리는 관계 신호에서 뺀다(당연히 높다). 목표 변수 분석에서는 합계가 있는 척도의 문항을 빼고 합계로 본다.

크기 기준은 r·ρ·V 0.1/0.3/0.5, η² 0.01/0.06/0.14(작음/중간/큼)다.

## 4. 결과

- **카드 (`hints`)**: 점수 순 상위 `maxHints`(기본 8)개. 관계 카드에서는 한 변수가 두 장을 넘지 않는다. 카드마다 제목, 근거(측도 = 값, n, 크기), 규칙으로 쓴 설명, 작은 그림, 제안 분석이 있다.
- 표: `overview`(한눈에 보기), `target`(목표 변수와 관련이 큰 변수), `signals`(찾은 신호 전체, 카드에 올랐는지 포함), `variables`(변수 프로필: 추정 유형, 결측, 요약값, 왜도, 메모).
- 그림: 카드 그림(`hint-sNN`), `target-rank`, `relation-map`(관련 크기 지도, 30개 변수까지), `distributions`(수치 변수 히스토그램, 36개까지).
- 알림: `sampled`(행이 `maxRows`보다 많아 표본 사용), `pairs_limited`(쌍이 5,000개를 넘음), `target_unusable`, `distributions_limited`, `no_signals`, `exploratory`.

## 5. 공통 결과 규격에 더한 것 (rsage)

- `rsage::rs_suggest(label, analysis, options, title)`: 다음 분석. 앱은 그 분석이 있으면 "열기" 버튼(같은 데이터, 이 옵션으로 새 탭)을, 없으면 "예정" 표시를 그린다. 길이 1 벡터가 JSON 배열로 남도록 배열 옵션은 `I()`로 감싼다.
- `rsage::rs_hint(id, title, text, evidence, kind, variables, plot, signal, suggestions)`와 `rs_result(hints = )`. 카드 그림은 섹션에 다시 나오지 않는다. 콘솔 출력과 Quarto(`knit_print`)에서도 카드가 맨 앞에 "살펴볼 만한 것"으로 나온다.
- 어시스턴트의 `get_analysis_result`·`run_analysis` 결과에 카드와 제안 옵션이 그대로 들어간다. 다른 모듈도 같은 함수로 제안을 낼 수 있다.

## 6. 변수 역할

| 역할 | bind | 종류 |
| --- | --- | --- |
| 목표 변수 | `target` | 하나, 선택 |
| 비교할 집단 | `compare` | 하나, 선택 (범주 2~6개) |
| 살펴볼 변수 | `variables` | 여럿 (비우면 모두) |
| 뺄 변수 | `exclude` | 여럿 |

옵션 `holdout {enabled, fraction, saveAs}`(기본 꺼짐, 30%, `explore_holdout`): 행의 일부를 무작위로 떼어 R 세션에 저장하고 나머지로만 탐색한다. 반복 측정이면 ID 단위로 나눈다. 카드의 제안 분석은 떼어 둔 데이터로 열린다(`rs_suggest(dataset = )`). 세션에 객체를 남기므로 어시스턴트가 켤 때는 R 실행 승인을 거친다.

## 7. 질문 맞춤 힌트 (0.2)

규칙 카드는 그대로 두고, 그 위에 어시스턴트가 사용자 질문에 맞춰 고른 카드를 얹는다. 계산은 하지 않는다.

- **입구**: 결과 위 질문 칸에 질문을 적고 "힌트 받기"를 누르면 어시스턴트 창에 준비된 요청이 간다. 채팅에서 "이 데이터에서 X와 관련된 것"을 물어도 같다. 질문 칩을 누르면 그 질문으로 다시 받는다.
- **어시스턴트가 보는 것**: `get_analysis_result`의 표(신호 표 전체, 변수 프로필, 목표 순위)와 범주 변수의 수준 이름(많은 순 10개, `variables` 표의 `levels`). ID·자유 텍스트로 추정한 열은 수준 이름을 내보내지 않는다. 원자료 행은 보내지 않는다.
- **도구 `set_exploration_hints(analysis_id, question, hints, questions, variables, ask)`**: 저장 전에 검사하고, 문제가 있으면 모두 적어 거부한다.
  - 카드마다 신호 ID(`s03`)를 하나 이상 인용해야 하고, 그 ID가 신호 표에 있어야 한다.
  - 제목과 본문의 숫자는 인용한 신호의 행, 그 신호의 규칙 카드, 관련 변수의 프로필·목표 순위 행, 개요 표에 있는 값이어야 한다(반올림 허용, 부호 무시). 10 이하의 정수(개수)와 `PHQ-9`·`phq9`처럼 이름에 붙은 숫자는 예외다.
  - 제안 분석은 설치된 분석이고 옵션이 그 스키마를 통과해야 한다. 확인용 데이터를 뗐으면 그 데이터로 연다. 카드에 제안이 없으면 인용한 신호의 규칙 카드 제안을 물려받는다.
  - 변수 뜻은 실제 열 이름에만 붙는다. 카드 8장, 질문 6개까지.
- **카드**: 근거 줄은 인용한 신호에서 앱이 만든다(어시스턴트가 쓰지 않는다). 그림은 인용한 신호의 규칙 카드 그림을 쓴다. 규칙 카드는 "규칙으로 찾은 카드 N장"으로 접힌다.
- **저장**: 분석 파일(`.rsage/analyses/<id>.json`)의 `guide`에 결과 `runId`와 함께 둔다. 다시 실행해 결과가 바뀌면 "이전 결과 기준"으로 표시한다. "지우기"로 없앤다.
- **되묻기**: 한 행이 무엇인지나 결과 변수가 애매하면 카드 대신(또는 함께) `ask`로 질문 하나를 남긴다.

## 8. 더 깊은 탐색 (0.3)

모두 신호를 더할 뿐이고, 같은 점수 체계로 카드에 오른다. 하나가 실패해도 나머지는 계속하고 경고 알림을 남긴다. 목표 변수와 거의 같은 변수(관련 크기 ≥ 0.95)는 모형·나무·상호작용에서 뺀다.

| 신호 | 계산 | 카드에 오르는 기준 | 다음 분석 |
| --- | --- | --- | --- |
| `model_importance` (목표 필요) | ranger 랜덤포레스트, 나무 300, 순열 중요도, OOB R²(수치) 또는 Brier(범주). 설명변수 결측은 중앙값·최빈 범주로 채움. 상위 수치 변수 2개의 부분 의존 | 상대 중요도 10% 이상 변수가 있으면 | 상위 변수로 회귀 |
| `model_hidden` | 모형 상위 3위 안인데 따로 본 관련 크기 < 0.1 | 그대로 | — (부분 의존 그림) |
| `subgroup` (목표 필요) | rpart 회귀나무, 깊이 ≤ 3, 잎마다 max(20, 5%)명. 이분 목표는 사건 비율 | 전체와의 차이 0.5 SD 이상 또는 10%p 이상 | 나눈 변수 두 개의 상호작용 회귀 |
| `interaction` (목표 필요) | 목표의 상위 연관 6개와 모형·나무가 쓴 변수의 모든 쌍, a×b 모형과 a+b 모형의 R²(이분·개수는 McFadden 의사 R²) 차이 | ΔR² ≥ 0.02, 상위 2쌍 | 상호작용 항을 넣은 회귀 |
| `clusters` | 수치 변수 주성분(분산 80%)으로 k-평균 k = 2~5, 무리마다 최소 5%. 3,000행 표본 | 평균 실루엣 ≥ 0.5 | — |
| `anomaly` | 수치 변수의 Mahalanobis 거리, 기준 χ²(1 − 0.05/n) | 1개 이상, 5%(최소 3개) 이하 | 데이터 점검 |
| `compare`, `group_shift` (`compare` 필요) | 집단(2~6개)마다 평균(SD) 또는 치우친 변수는 중앙값[IQR], 범주는 n(%). 집단 쌍 가운데 가장 큰 SMD(범주는 Yang & Dalton) | 요약 카드는 항상, 변수 카드는 SMD ≥ 0.2 상위 2개 | t 검정·분산분석·교차표(예정) |

이상 사례 표에는 행 번호, 거리, 가장 동떨어진 변수의 z만 둔다(원자료 값은 어시스턴트에게 가지 않는다). 표 1은 척도 문항 대신 합계를 쓴다.

## 9. 앱과 이어지기 (1.0)

- 어시스턴트: 데이터를 막 불러왔거나 "두루 살펴봐", "무엇을 분석할까"라고 하면 탐색 안내를 먼저 실행하고 `set_exploration_hints`로 질문에 맞춘다(시스템 지시). 카드에서 분석을 열 때 `run_analysis`에 `from_analysis_id`, `from_hint`를 넘긴다. 어시스턴트 첫 화면 예시에 "study 데이터를 두루 살펴보고 무엇을 분석할지 알려 줘"를 넣었다.
- 환경 창: 데이터 프레임 줄의 **탐색** 버튼이 탐색 안내 탭을 연다(같은 데이터·옵션이면 이전 탭을 다시 쓴다). 결과가 없으면 바로 실행한다.
- 후속 분석 기록: 카드의 열기 버튼이나 어시스턴트가 연 분석은 `from: { analysis, hint }`를 저장한다. 같은 분석을 다시 열면 처음 카드를 유지한다.
- 탐색 기록: "살펴볼 만한 것" 제목 옆 **탐색 기록 넣기**가 열린 .qmd의 커서 아래에 넣는다. 날짜와 "확인할 가설"이라는 안내 인용문, 질문, 탭이 먼저 보이는 카드(현재 결과의 어시스턴트 카드, 없으면 규칙 카드)의 제목·근거·설명, 이 탐색에서 연 분석과 실행 여부, `rsageExplore::analyse()` 청크. R 스크립트가 열려 있으면 .qmd를 열라고 알린다. 커서가 YAML 머리말이나 청크 안에 있으면 그 블록 뒤에 넣는다. 비주얼 모드에서는 커서가 있는 블록 뒤에 넣는다. 같은 청크 이름이 이미 있으면 `-2`, `-3`을 붙인다. 문서가 그 데이터를 만들지 않으면(대입이나 `assign`) 렌더하려면 앞 청크에서 읽어 들이라는 안내를 인용문에 덧붙인다. 분석 탭의 "문서에 넣기"도 같은 위치·이름 규칙을 따른다.
- 다른 모듈의 제안: 회귀 모듈 카드 제안은 0.1부터 있다. 데이터 점검 모듈의 제안 카드는 dlookr가 필요한 테스트를 돌릴 수 있을 때 붙인다(다음 작업).

## 10. 검증

`r-packages/rsageExplore/tests/testthat/test-analyse.R`: 신호를 하나씩 심은 표에서 각 신호가 잡히는지, 서로 독립인 잡음 표에서 관계 신호가 나오지 않는지, ChickWeight에서 반복 측정을 찾는지, 목표 변수 유형별 회귀 종류, 큰 데이터 표본, 조사(와/과) 처리, result.json의 카드와 제안 옵션 형식.

앱 테스트(`packages/host/test/analysis.test.ts`): 모듈 등록과 form 검사, 실제 R 세션에서 airquality 실행, 카드의 모든 제안이 대상 모듈 스키마를 통과하는지, 제안한 회귀가 실제로 실행되는지, `set_exploration_hints`가 지어낸 숫자를 거부하고 맞는 카드를 저장하는지. R 테스트(0.3): 심은 상호작용(따로는 관련 없는 x가 모형에서 중요, 상호작용 카드의 회귀 옵션에 상호작용 항), 뚜렷한 무리 3개, 한 행만 패턴에서 벗어난 표, 잡음 표에서 무리·이상 행이 없는지, 표 1의 SMD와 척도 문항 처리. `packages/host/test/guide.test.ts`: 숫자 읽기(이름 속 숫자, 천 단위 쉼표), 반올림 대조, 문제 목록, 제안 검사, 확인용 데이터. 1.0: `packages/ui/test/explorationLog.test.ts`(카드·질문·이어서 연 분석·청크, 지난 결과의 어시스턴트 카드는 쓰지 않음), analysis.test.ts의 `from` 저장과 재사용.
