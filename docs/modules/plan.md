# 분석 계획 모듈 스펙 (`org.rsage.plan`)

_2026-11-14 · 검토 문서: [분석 제안 모듈: 기술적 가능성 검토](https://claude.ai/artifact/7Gny51Y4Du6PQ3ftkf4X1g)_

## 1. 목적

"이 질문에는 어떤 분석을 써야 하나"에 답한다. [탐색 안내](explore.md)가 데이터에서 가설을 찾는다면, 분석 계획은 정해진 질문을 확인할 방법을 고른다.

- **LLM은 고르지 않는다.** 어시스턴트는 사용자의 질문을 역할(결과 변수, 집단·설명 변수, ID, 목적, 설계)로 옮길 뿐이다. 분석은 R이 계산한 설계 프로필과 아래의 고정 규칙이 고른다. 같은 질문과 데이터면 언제나 같은 계획이다.
- **원자료는 어시스턴트에게 가지 않는다.** 카드와 표에는 요약 수치만 있다.
- **계획은 실행 전에 남는다.** 결과에 계획 시각을 적고, 카드의 버튼이 옵션이 채워진 분석 탭을 연다(`from`으로 계획을 기억).

## 2. 입력 (`options.schema.json`)

| 옵션 | 뜻 |
| --- | --- |
| `question` | 사용자의 질문 (표시만, 규칙에 쓰지 않음) |
| `goal` | `auto` · `compare` · `relate` · `predict` |
| `outcomes` | 결과 변수. 집단 없이 수치 열이 둘 이상이면 같은 대상의 반복 측정(넓은 형식) |
| `groups` | 집단 변수나 설명변수 |
| `id` | 긴 형식에서 대상 ID |
| `design` | 결과 변수가 여럿일 때 `auto`(이름으로 추정) · `paired` · `independent` |

## 3. 설계 프로필

변수마다 유형(연속, 개수, 순서·점수, 이분, 범주, ID, 텍스트 …), n, 결측, 범주 수, 평균, SD, 왜도. 수치라도 값이 5가지 이하면(용량 0.5/1/2, 코드 1/2/3) 집단을 나누는 변수로 본다. 집단 비교면 집단마다 n, 평균, SD, 중앙값, 왜도, Shapiro p.

## 4. 규칙

| 상황 | 주 분석 | 함께·대안 | 점검 카드 |
| --- | --- | --- | --- |
| 수치 결과 + 두 집단 | Welch t 검정 | 작은 집단(n < 30)이 치우침(|왜도| ≥ 1)이나 Shapiro p < .05, 또는 순서 점수면 Mann–Whitney 함께. 대안: 범주 설명변수 선형 회귀(개수면 Poisson) | 집단 크기 3배 이상 차이, n < 2 |
| 수치 결과 + 셋 이상 집단 | 고전 F + Welch 분산분석 + Games–Howell | 같은 조건이면 Kruskal–Wallis + Dunn 함께. 대안: 회귀 | 집단 9개 이상 |
| 수치 결과 + 두 요인 | 이원 분산분석(유형 III) | 대안: 상호작용 회귀 | 빈 칸이면 주효과 회귀로 바꿈 |
| 이름이 `x_pre`/`x_post`인 두 열, 또는 설계 `paired` | 대응 t 검정 | 차이가 치우치면 Wilcoxon 함께, 아니면 대안 | 짝이 맞지 않는 행 |
| 셋 이상의 반복 측정 열 | 혼합모형·반복측정 분산분석 (예정) | 대안: 쌍별 대응 t 검정(최대 6쌍, 보정 안내) | |
| ID가 반복되는 긴 형식 | 혼합모형 (예정) | | 행 독립 가정 위반, 두 시점이면 넓은 형식 변환 |
| 범주 결과 + 범주 집단 | 교차표 (기대 빈도 < 5가 20% 넘으면 Fisher 자동) | 이분 결과면 로지스틱 회귀 | |
| 연속 설명변수가 있거나 집단 변수 셋 이상 (`relate`) | 결과 유형별 회귀: 선형 / 로지스틱(사건 = 드문 값) / Poisson(분산/평균 > 1.5면 음이항) | 단순 회귀면 상관(예정), 순서 점수면 순서 로지스틱(예정) | EPV(적은 쪽 사건 / 설명 자유도) < 10, 행 / 설명 자유도 < 15 |
| `predict` | 위와 같음 | | 확인용 데이터 떼어 두기(탐색 안내) |
| 결측으로 5% 이상의 행이 빠짐 | | | 결측 분석 열기 |
| 집단 없이 수치 결과 하나 | 일표본 t 검정(기준값은 탭에서) | | 무엇과 비교할지 되묻기 |

판단마다 `rules` 표(확인한 것, 값, 판단)에 한 줄씩 남는다.

## 5. 결과

카드 제목 "분석 계획"(`rs_result(hints_title =)`): 추천 → 대안 → 예정 → 점검 → 되묻기. 주 카드에 집단별 상자그림. 표: `question`(이렇게 이해했습니다), `variables`, `groups`, `rules`(판단 근거), `plan`.

## 6. 앱과 어시스턴트

- 메뉴: 데이터 준비 › 분석 계획.
- 시스템 지시: 사용자가 어떤 분석·검정을 쓸지 물으면 직접 고르지 말고 분석 계획을 실행한 뒤, 주 카드의 옵션 그대로 `run_analysis`(`from_analysis_id`, `from_hint`)를 부른다. 지침은 `modules/plan/ai.md`.
- 탐색 안내 카드의 t 검정·분산분석·교차표·대응 t 제안은 이제 [집단 비교](compare.md) 모듈로 열린다(같은 Welch 기본값).
