Use this analysis whenever the user asks for a regression or GLM with one outcome: linear regression, multiple regression, hierarchical (blockwise) regression, logistic or probit regression, Poisson or negative-binomial count regression, rate models with an exposure, Gamma models, interactions/moderation, adjusted means or predicted probabilities, model comparison, regression diagnostics or stepwise selection. Prefer it to writing lm/glm code with run_r: it fits every model on one documented sample, checks the outcome and terms, and the result opens in the app's analysis tab where the user can adjust it.

Options

- `outcome.variable` and `model.family`: gaussian (numeric outcome), binomial (two values; probabilities), poisson or negative_binomial (non-negative integer counts; prefer negative_binomial when the dispersion check shows overdispersion), gamma (positive, right-skewed), quasibinomial/quasipoisson (overdispersion without likelihood: no AIC, no LR tests, no stepwise). `model.link` "default" is the canonical link (gamma: log).
- Binomial: if the outcome is not 0/1 or TRUE/FALSE, set `outcome.event` to the value counted as the event (exactly as in the data). For one row per group with successes and trials, set `outcome.encoding: "grouped"` and `outcome.trials`.
- `predictors.continuous` and `predictors.categorical`: put numeric codes that mean categories (e.g. 1/2/3 for groups) in categorical.
- Terms and models are structured data, never formula text. `terms`: `{id, kind: "main", variable}` for each predictor and `{id, kind: "interaction", components: [main term ids]}` (2- or 3-way). `models`: `[{id, label, termIds, intercept}]`. Strong hierarchy is required: an interaction's lower-order terms must be in the same model. If you give predictors but no terms, one model with every main effect is made (a note says so).
- Hierarchical regression: models m1 ⊂ m2 ⊂ m3 with `comparison.enabled: true`. With no `comparison.pairs`, each model is tested against the previous one when nested (F for linear, likelihood ratio for binomial/Poisson/negative binomial) and ΔR² is reported for linear models. All models use the same rows (`missing.sampleScope: "shared"`), so comparisons are valid.
- `coding.factors`: `{variable, reference, contrast: "treatment" | "sum"}`. Use sum coding with `inference.termTests: "type3"` when the model has interactions. `coding.transforms`: `{variable, transform: "none" | "log", center: "none" | "mean" | "value", centerValue}`; centre continuous predictors that appear in interactions so main effects are effects at the mean. Log of values ≤ 0 is refused, never patched.
- `inference.termTests`: "hierarchical" (default; drops a term together with the interactions containing it), "type1" (order-dependent), "type2"/"type3" (car::Anova).
- `offset`: for counts with different exposure (person-time, population) use `mode: "exposure"` with the exposure column; coefficients are then rate ratios per exposure unit.
- `effects`: `enabled`, `kind` "means" (adjusted means or probabilities by `focal`), "slopes" (slope of a numeric `focal`, by `moderator`), "contrasts" (pairwise differences between focal levels, `adjust` holm by default); `modelId` null means the last model; `marginalization` "empirical" averages over the sample, "reference_grid" fixes others at typical values; `scale` "response" or "link"; `at` rows `{variable, values: "20, 40"}` on the original scale.
- `diagnostics`: `residuals`, `collinearity` (VIF/GVIF), `influence` (flags rows with large Cook's distance or leverage; nothing is removed), `dispersion` (binomial, Poisson), `zeros` (counts), `calibration` (binary: deciles and Brier score). `modelId` null is the last model.
- `selection.method: "stepwise"` runs MASS::stepAIC from `sourceModelId` (null = last model) within `candidateTermIds` (empty = that model's terms), keeping `forcedTermIds`, by `criterion` AIC or BIC. Only on request; it is exploratory and its p-values are optimistic. It suggests a model; it does not change the user's models.
- `export.models` / `export.augmented` with `saveAs` put the fitted models, or the analysis rows with fitted values and residuals, in the user's R session; the app asks for approval. Only when the user wants them.

Not in this version (say so instead of improvising): LASSO/elastic net/ridge, selection stability by resampling, bias-reduced (Firth) logistic, robust or cluster standard errors, polynomial and spline terms, mixed, Bayesian, survival and multinomial models.

Reporting

Quote numbers from the result tables: coefficients with CIs (and exp(b) for logit/log links, saying odds ratio or rate ratio), term tests, the fit table (R² only for linear models; Tjur/McFadden R² for binomial are different measures), ΔAIC/ΔBIC and the nested tests, and the sample table (rows dropped for missing values). Mention notes marked as warnings, especially separation, rank deficiency, non-convergence, overdispersion and post-selection inference. With interactions, main-effect coefficients are effects when the other variable is 0 or at its reference level; use the effects (slopes) table to describe moderation. Do not call a model "best" from one criterion. Each table and plot carries a `description` saying how to read it.
